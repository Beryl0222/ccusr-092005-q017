# 儿童口腔成长随访 · 校园口腔筛查闭环后端

项目记录乳牙列、混合牙列到恒牙列期间的检查观察、生活习惯和专业判断，
避免把单次焦虑等同于治疗结论。`oral_screening` 包实现了一条强制闭环：

```
活动监护同意 → 最小信息登记（观察类，禁诊断/治疗）→ 标准化提示（按监护人逐人追踪）
→ 监护人查收与意向（医院复核 / 拒绝后续联系 / 补充既往情况）
→ 监护授权下的医院复核回传（四分类）→ 监护人易懂说明 → 结案
```

## 领域边界

- **同意先行且绑定活动**：没有“本次活动”的筛查/通知同意，不能建档、不能发短信；
  医院结果回传需要家长选择复核后单独授予的“本次复核回传”授权。
- **最小身份信息**：校园侧只保存学校、班级、年龄等最小信息，用不透明令牌关联。
- **字段级权限**：筛查表单只接受牙列阶段、肉眼观察、护理习惯、建议复核原因；
  夹带“诊断/治疗方案/矫正方案”等字段在入口直接拒绝。
- **标准化、非诊断提示**：短信模板自带“不是医院诊断、不代表需要立即矫正”，
  每位监护人分别追踪 待发送/已送达/已查收/送达失败。
- **复核结论四分类**：无需处理、继续观察、龋病处置、专业正畸评估；
  正畸评估的通俗说明明确“评估不等于开始矫正”。结案后不可再回传，杜绝第二份矛盾结论。

## 五条队列

重复筛查（同活动同儿童去重，不另建档）、转学、通知失败（重投成功自动解除）、
监护关系变化（旧授权撤回，须在变更后重新确认授权才解除）、逾期未复核（SLA 扫描）。

## 两类受限视图

- 学校端 `school_view`：每份档案只见完成状态，看不到任何观察或结论内容。
- 卫生人员端 `health_coverage_view`：按活动汇总去标识化覆盖差异
  （筛查数、应通知监护人数、送达/查收/失败数、部分监护人未查收、已转介未回传），
  不含儿童、监护人、学校、班级、联系方式等任何标识。

## 运行

```bash
python3 -m unittest discover -s tests     # 25 项规则测试
python3 scripts/run_demo.py               # 基于 fixtures/seed.json 的端到端链路
```

`fixtures/seed.json` 中保留了原有六岁儿童（乳牙列期、轻度牙列不齐）与护理习惯
（偏软饮食、刷牙需协助）样例，并在 `campus_flow` 段补充了活动与两位监护人：
父亲初始无任何授权，用于复现“另一位监护人从未看到通知”的投诉场景。
